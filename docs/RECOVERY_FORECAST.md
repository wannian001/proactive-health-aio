# 个人历史恢复预估

本地实现日期：2026-10-18。功能属于实验性历史参考，尚未建立个人前瞻准确度。

## 页面与记录

恢复页用两个独立卡片显示当前酸痛、当前精力，以及有依据时的「预计多久后 → 到什么程度」。
人体点选查看同部位历史，精力始终表示全身感受。未知不等于零，未填写部位保持未知。

- 新增「记录此刻精力 / 酸痛」：原始 0–10 分，服务器保存带时区的采集时间。
- 原有早晨 CSV 仍保留酸痛 0–3、精力 0–5、恢复感受 2/5/8。三者不混合、不硬换算。
- API 可保存 `[下限, 上限]` 自评区间及短备注。页面显示原区间；绘图中点不当作精确标签，
  这类记录不参与精确分值拟合。普通页面输入目前接受单个分值。
- 当前时间记录有效期为 24 小时；更早的记录不冒充当前状态。历史日期查询只用当时可见数据。
- 日采样只给天数范围。只有记录密度足够时才启用小时区间，绝不从每日 CSV 猜出「18 小时」。
- 外圈紫色弧表示预估区间中点占标注时间刻度的比例（24 或 168 小时），仅为摘要；
  不是完成百分比、置信度或个人恢复概率。无时间预估时不画外圈。
- 设备指标各自显示实际记录日期；训练明细缺失表示「暂无训练明细」，不推断没有运动。

## 带时间的算法（timestamped_intervals_v1）

1. 每个部位独立建历史，精力单独建历史。不拼接不同人的数据，也不把全身酸痛当局部严重度。
   查询最多过去 365 天的最近 2,000 个时点；同一时点保留最后一条有效观察。
2. 精力目标取之前 28 天、相近本地时段（±3 小时）、至少 10 个不同日期的自评中位数。
   每日最多一票，不包含当天；每段历史的目标在起点冻结。近期常态不是健康标准。
3. 酸痛目标为 `max(0, min(2, 当前值 - 1))`：较明显时观察何时降至 2/10，
   已较轻时观察至少再减一分。不是损伤痊愈或训练许可。
4. 相似起点按距离当时目标的差值匹配，容差 1 分；一段必须观察到目标后，才允许开始下一段。
   不把同一段连续多次记录算作多个独立恢复案例。本版时间记录分支尚不按症状持续阶段细分。
5. 每段保留 `[最后未达目标时点, 首次达目标时点]`。最多追踪 168 小时；断档或未完成时上界为未知。
   至少 12 个有效采样间隔且中位间隔 ≤8 小时时采用小时分辨率，允许最大间隔 8 小时；
   其他情况允许最大间隔 36 小时，并向外取整到天。重复打卡不缩窄实际观察区间。
6. 至少 5 段历史、3 段有观察终点才估范围。使用历史下界的第 25 百分位与上界的第 75 百分位，
   未结束片段的上界按无穷计入；上界不可定时放弃出数。该范围是经验分布边界，不是置信区间。
   至少一段匹配记录须在最近 90 天内。
7. 时间窗口从最后一次真实自评起算，刷新页面不会重新开始倒计时。原窗口过期则提示重新记录。
8. 用每个历史起点之前的前缀重新估计并检查结果。误差定义为预测中点到实际观察区间的距离；
   落在区间内计 0，不能称为精确恢复时刻误差。未知终点不计入误差。

## 设备背景与原日表算法

两个分支都可匹配起点之前三个完整日的睡眠、训练分钟，以及 HRV / 静息心率相对此前 28 天
个人基线的偏差。睡眠容差 60 分钟；训练容差为 30 分钟或当前三日总量的一半（取大者）；
HRV 和静息心率偏差以个人四分位距标准化，容差 1.5。HRV 尺度下限 2 ms，心率下限 1 bpm。
需要三日近期值与至少十日基线。进一步匹配后不足五段有随访历史时退回自评匹配，并在依据里说明。
设备数据提供背景条件，不直接生成精力或酸痛标签。

原日表继续使用 `personal-trajectory-v1`：酸痛至少降低一档；精力回到过去 28 天至少十次自评的
中位数；匹配相同持续阶段（长于七天的另组），跟踪七天，缺失按右删失，采用离散 Kaplan–Meier
第 25/75 百分位。至少五段有随访、三段事件、未确认/无随访合计不超过 40%，否则不给时间。
两个分支的量表、采样精度和误差口径均分别保留。

这些窗口、门槛与容差属于可检查的工程参数，未经临床验证。新训练、作息改变及未记录因素
可能改变结果；小时分支目前只有合成轨迹验证，不能声称已被真实小时级数据验证。

## 课程方法复用与公开数据核对

只读参考了可视化课程 PMData 项目的分部位表达、个人基线和按时间验证方法，以及机器学习
课程中的数据泄漏控制。未修改课程成品；NHANES 的抑郁标签没有用于恢复模型。

`python3 -m healthaio.benchmark_recovery` 可对已有 PMData `daily.csv` 运行独立只读基准：
参与者分开，2 月选择仅历史/带设备背景两种策略，3 月测试；随访结局不跨越验证/测试边界。
每个测试起点只用此前记录。PMData 的 readiness 不是本人的精力，整体 soreness 不是局部严重度。
基准衡量日表方法的迁移可行性，不导入任何参与者到个人资料，也不用于生成本人的历史记录。

2026-10-18 本地回放（16 位参与者，2,367 日行；当前源 SHA-256
`aa209b4bf1ba7bfbca9a3caf35f8411937de0362853e5e9876fc412d7eadb7d3`）：

| 端点 | 验证集选择 | 3 月符合起点条件 | 出具范围 | 已知终点 / 未确认 | 已知终点范围命中 | 中位时间 MAE |
|---|---|---:|---:|---:|---:|---:|
| readiness | 仅历史 | 78 | 27 | 22 / 5 | 20 / 22 | 0.591 天 |
| 整体 soreness | 设备背景匹配 | 272 | 39 | 25 / 14 | 20 / 25 | 0.840 天 |

这是按日预估案例数，不是独立受试者数。覆盖率有限，误差只在已知终点上计算；未确认结局可能
不是随机缺失，不能把命中比例称为个人准确率。较复杂的策略并未稳定优于历史基线。
完整机器可读报告保存为本次本地 QA 附件；不是个人训练成果。

## 接口、隐私与本地接入

- `GET /api/recovery` 返回 `forecast` 与 `current_ratings`，包括原量表、目标、范围、依据及状态。
- `POST /api/recovery-checkin`：`request_id`、`kind` (`energy` / `soreness`)、
  `region`（精力为 null；酸痛为支持的单部位）、`value`（0–10 或有序二元区间）、可选 `note`。
  同源校验、输入校验、写锁、追加写及 fsync；重复 request_id 幂等，冲突内容拒绝。
  记录放在配置目录的私有 `recovery_observations.jsonl`，新文件权限 0600。
- `range_rating`、`baseline_needed`、`insufficient`、`few_outcomes`、`incomplete`、
  `missing_current`、`old_history`、`refresh_needed` 等均有具体提示。没有时间就不伪造预估。
- 旧 `POST /api/checkin` 继续支持原 0–5 精力，`levels: null` 只存精力，`levels: {}` 明确没有酸痛。
- `python3 -m healthaio.personal_import --source <个人系统入口> --out <新私有目录> --until YYYY-MM-DD`
  默认只读预览；加 `--apply` 创建独立私有配置。现有目标或源/代码目录内目标会被拒绝。
  通过源系统 resolver 读取指定派生表，仅保留必要数字和日期，过滤 fixture/test/excluded。
  保存源哈希；不改原件、不导入自由文本/凭据、不猜测训练时间或主观状态。
  这是指定日期的本地快照，不是自动同步或云端发布。

## 验证命令与依据

```sh
python3 -B -m unittest discover -s tests
python3 -B -m healthaio.benchmark_recovery --pmdata-dir <已有处理表目录> --out <本地QA报告.json>
```

测试使用合成数据覆盖时间隔离、独立片段、未完成结局、量表、区间自评、旧记录、同源保存与
私有导入。浏览器另检查中文/英文、桌面/手机、保存后刷新，以及真实资料的数据不足状态。

时间验证原则可参见 [scikit-learn TimeSeriesSplit 官方文档](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)。
[NHLBI 睡眠评估说明](https://www.nhlbi.nih.gov/health/sleep-deprivation/diagnosis-treatment)区分睡眠记录和主观感受；
两者均不为本项目的个体恢复时间参数提供有效性背书。
