# Rest & rewards · 休息与奖励

这部分接在 AIO 原有的「记录 → 对比 → 调整 → 跟进」之中，服务于持续的投入、恢复和享受。保留四组主导航。

| 现有位置 | 新增行为 |
|---|---|
| 今天 | 日环和早上那张卡不变。「今天该调整的」最上面多一行「此刻」：这一刻的休息建议，点进休息与奖励；它说的是现在，不算在三件里。早上卡里一行显示你此刻说过的感受，链接到恢复页去记。 |
| 身体状态 → 恢复 | 「此刻怎么样」卡：此刻精力（0–10）、早上的恢复感受、哪里酸、精神状态、任务难度，一次保存。感受只在这里说。 |
| 生活习惯 → 休息与奖励 | 这一刻的建议和依据、两小时少打扰、活动卡片、开始 / 结束 / 取消、独立的庆祝计划。 |
| 计划与跟进 → 跟进 | 进行中的活动、试过的恢复方式（实际活动记录、可修改的主观反馈、开始活动时的依据快照）。 |

2026-10-19 收敛：原先今天页、休息页、恢复页各有一份「简单说说现在的感觉」，今天页的日环被折叠在建议下面，试过的活动在休息页和跟进页各一份。现在感受只在恢复页说一次，日环回到今天页首屏，试过的活动只在跟进页。

## 按你自己的记录（2026-10-19）

- 活动库按你的回答排序：每种活动做完后几次“变好”、几次“开心”，在答过的次数里占多少；答满两次才参与排序，样本太少的放后面。卡片上写着这些数。
- 建议直接点名一项、点一下就开始：身体信号低于平常或你说累了，推最常让你变好的那项（至少一半次数变好才点名）；做完一件事（截止日在昨天或今天、已标记提交或完成的作业；今天 20 分钟以上的训练），推又变好又开心的那项，前一天娱乐和社交超了上限时不推“玩一点真正想玩的”。奖励只是多一个好建议，休息仍然不需要用完成任务来换。今天页的「此刻」那一行会显示。
- Mac 应用看到你在电脑前连续 50 分钟以上后起身、3 分钟到 2 小时后回来，这次离开自动写成一次做完的休息（`op: auto`，活动 `break`，“离开电脑一会儿”），每次离开只记一次，可以给它填感受；“不算休息，删掉”写一条 `op: remove`。页面不能写 `auto`。
- 跟进页把试过的休息按活动汇总成一张表：做了几次、几次之后变好、几次开心；每一次的明细收在折叠里。

## 行为规则

- HRV、静息心率和睡眠沿用已有的个人 28 天基线比较。至少两项不如平常，且数据日期为今天，才触发身体恢复建议。最近三天中有至少两天如此，展示趋势背景；不是临床阈值。
- 自评疲劳、酸痛、精神疲劳或紧绷可独立触发轻松活动建议。自评只作为自评，不反推身体测量值。
- 身体感觉不再单独问，由同一张卡上的回答得出：精力 3 分及以下记为「累了」，6 分及以上记为「还舒服」，今天有部位明显酸或更重记为「有酸痛」（酸痛优先）。精力 4–5 分且没有明显酸痛时不记身体感觉。这两个分界也是首版产品参数。
- 当前感受参考四小时；少打扰持续两小时。这是首版产品参数，尚未经过个人效果验证。到期由下一次读取页面时重新判断。
- 最近活动反馈「更累了」时，倾向更轻松的休息，不催促工作。只有同时报告「身体还舒服」和「无聊」，才邀请用户自己选一点挑战。
- 日程显示未来三天计划中的工作 / 上课时长与未完成截止项；重叠时段只计一次。不换算成精神压力分数。无来源保留未知。
- 今日饮食仅显示到当前时刻已录入的碳水和记录条数，不当作完整摄入，不估算多巴胺，不用后来的食物解释更早的 HRV。
- 休息不需要完成任务才能获得。庆祝是独立计划，可以没有里程碑；保存计划不等于已经做过。
- 活动没有强制计时。用户开始、结束、取消分别记录；「变好 / 差不多 / 更累」和「开心 / 一般 / 不喜欢」分开，均可不答。
- 普通调整建议在少打扰或自评投入时收起，已有的训练记录弹窗也暂缓。休息页不弹训练记录提示；运动记录入口仍保留。

## 本地记录与接口

`restore.jsonl` 与 `healthaio.toml` 同目录，已加入忽略规则，不放进 CSV 健康测量表。新文件权限为 `0600`。已有数据不迁移。

- `GET /api/restore` 与 `healthaio page restore`：同一份当前状态、活动和庆祝记录。
- `POST /api/restore`：沿用当前应用的同源和配对设备限制；请求体上限 4 KB。
- 事件类型：`checkin`, `quiet`, `resume`, `start`, `finish`, `cancel`, `feedback`, `reward_plan`, `reward_done`, `reward_cancel`, `auto`（只由应用写）, `remove`。
- 每次请求必须有独立 `request_id`。相同 ID 和相同请求重试只返回原回执；换内容复用 ID 会被拒绝。
- 服务端生成带时区的时间和事件 ID，在已有 writer lock 下追加并 `fsync`。同时只能有一个进行中的活动；结束后才可补充反馈。反馈修改追加新事件，不抹去旧事件。
- 开始事件保存所用规则版本、测量日期与比较值、当前自评和日程 / 饮食背景。之后重算的建议不会覆盖当时的依据。
- 遇到损坏日志，停止该日志的读取 / 写入并报错，不静默把损坏记录当成未发生。保留原文件后再修复。
- 记录列出最近 30 项活动；进行中的活动始终单独显示。所有待进行的庆祝保留显示，已结束庆祝显示最近 30 项。

静态站保留浏览功能，但所有保存按钮禁用；API 客户端也拒绝静态模式写入。本地 `--demo` 使用独立临时目录，所有页面明确标记演示数据。测试与演示中的自评不代表使用者的真实状态。

## 当前边界与下一步

这版包含本地可持久化的完整交互，不包含后台 HealthKit 采样、系统通知推送、抑郁风险预测或自动修改日历。尚未验证真实 iPhone / Mac 安装包，也未发布远端。

后续若接入更主动的提醒，先保留 HRV 采样时间、来源和样本数，明确提醒频率与静默策略，再做设备端推送。活动推荐可在积累个人反馈后按偏好排序；当前六项是可选活动库，并没有宣称哪项对某个人更有效。

## 研究依据与解释边界

- [Quigley et al., 2024, HR/HRV measurement and interpretation guidance](https://onlinelibrary.wiley.com/doi/full/10.1111/psyp.14604)：测量方法与生理背景限制了可以作出的推断。
- [Verkuil et al., 2016, daily-life HRV and psychological stress](https://pubmed.ncbi.nlm.nih.gov/27150960/)：研究考虑活动等代谢因素，不能把日平均 HRV 直接当作个人精神压力诊断。

文献用于限制解释范围。当前提醒规则、四小时参考期和活动菜单都是产品设计选择，不是经过临床验证的医学算法。

## 专注额度与可持续的节奏（2026-10-19）

规则和参数在 `healthaio/modules/focus.py` 开头。

- **深度专注**：屏幕使用时间里工作或学习类应用一口气 25 分钟以上的段（中间离开不到 3 分钟不算断），每段加起来。手机穿插进来的那几分钟会打断连续段：一分钟在手机上，就是一分钟不在工作上。没有设备能测“创造力”或“脑力”，深度专注是能测到的最接近的东西。
- **专注额度**（恢复页第三个圈）：过去 90 天里和这天最像的 10 天你实际做到多少深度专注，按昨晚睡眠和今早 HRV（相对它自己 28 天的平常）找最像的，工作日只和工作日比（够 7 天时）；中位数是额度，中间一半是范围。少于 7 天就不给额度。今天已做的深度专注填进圈里，旁边写屏幕时间截至几点。工作和学习类应用上用了 30 分钟以上、却没有一段满 25 分钟时，卡片直接说“总被打断”。
- **可持续的节奏**（休息与奖励页，`#restore/rhythm`）：回看 56 天，每天的额度只用这天之前的数据算。超额度 = 比范围上沿还多、且至少 30 分钟；按时起身 = 没有连续超过 90 分钟的一段，或那天记过一次休息；守住节奏的一天 = 没超额度且按时起身；节奏稳的一周 = 至少 5 天能判断、其中 5 天守住。连续 3 天超额度，建议把接下来三天里课和工作最少的半天留空；连续 3 周节奏稳，出一个庆祝计划（写进 `restore.jsonl` 的 `reward_plan`，带 `for: rhythm`，每一轮只出一次）。今天页的“今天该调整的”里也会出现这两种提醒。
- 奖励的是守住节奏，不是做得多：做得比额度多不加分，休息仍然不需要挣。
